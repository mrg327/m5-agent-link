# Protocol: names, numbers, versions

Rules for the wire protocol between `agentlinkd` and a device, and for how each language spells a
protocol name. Issue 20261122-db53 (phase 0). The schema is
[`protocol/agentlink.cddl`](../../protocol/agentlink.cddl); what the messages mean is in
[`docs/design/PROTOCOL.md`](../design/PROTOCOL.md). This page does not restate either.

The model is Protocol Buffers: names are defined once in a schema with fixed casing, each generator
turns them into its language's idiom, and a number once used is never used again
([protobuf style guide](https://protobuf.dev/programming-guides/style/),
[proto3: reserved fields](https://protobuf.dev/programming-guides/proto3/#fieldreserved)). The CDDL
plays the role of the `.proto` file. CDDL itself is [RFC 8610](https://www.rfc-editor.org/rfc/rfc8610).

Each rule ends with how it is checked: `checked: <tool>`, `review`, or `planned: phase N`
([README](README.md#how-a-rule-becomes-enforced)).

## 2. Naming in the CDDL

Write CDDL names in lower snake_case. The C codec takes its identifiers from them, so a rename
changes the C code and needs a `regen.sh` run.

- **PROTO-1. Message types are `mt_<name>`, the envelope rule is `msg_<name>`, and a debug
  message's `<name>` starts with `dbg_`.** All 37 follow this. The body rule is usually `<name>`;
  when the body has another name, the `msg_` line says so (`msg_session_upd` carries `session`,
  `msg_cfg` carries `device_cfg`, `msg_ping` and `msg_pong` carry `empty`). `review`; `planned: phase 2` (generator)
- **PROTO-2. An enum is a union of named constants, `<enum> = <enum>_<value> / …`, and every value
  carries the full enum name as its prefix.** This is protobuf's prefix rule, and zcbor needs it
  because it has no `&( … )` enums and labels must not collide with rule names
  ([protocol/README.md](../../protocol/README.md)). Two enums break it today: `pointer_btn`
  (`pointer_left`, `pointer_right`) and `scroll_unit` (`scroll_lines`, `scroll_pages`,
  `scroll_to_end`). Do not copy them; renaming them is a C codec change, so it waits for the generator.
  `review`; `planned: phase 2`

  ```cddl
  ; good                               ; bad: prefix is not the enum's name
  fw_status = fw_status_go / …         pointer_btn = pointer_left / pointer_right
  fw_status_go = 0                     pointer_left = 0
  ```

- **PROTO-3. Every map key line ends with `; <name>`, and that first word is the key's symbolic
  name.** Vectors, `agentlink decode`, the trace, the Rust field and the JS spec all use it. Write the
  comment's prose after the name. `review`; `planned: phase 2` (the generator reads it)
- **PROTO-4. Symbolic names are short and lower case:** a common word (`text`, `sid`, `seq`) or an
  abbreviation of at most 4 letters for a key that is sent often (`st`, `br`, `tst`, `snz`). Explain
  an abbreviation in the same comment. Reuse an existing name for the same idea: `sid` is always a
  session id, `rid` a request id, `aid` a recording, `kid` a keyboard opening, `seq` a per-stream
  counter, `off` a byte offset, `ts`/`t0`/`at` unix seconds, `*_ms` milliseconds. `review`
- **PROTO-5. Every array is bounded (`[0*8 foo]`), every byte string is sized (`bstr .size
  (0..240)`).** zcbor gives each a fixed buffer in the device; an unbounded array silently gets
  zcbor's default of 3 entries. `review`
- **PROTO-6. A comment states the proto minor that added a key, message or value, and the design
  doc that defines it**: `; qd … (proto 0.17, PROTOCOL.md §4b)`. `review`

## 3. How each language spells a CDDL name

Protobuf's casing rules, mapped onto our languages. The CDDL spelling is the source; the others
follow mechanically from it.

| CDDL | C codec (zcbor, generated) | C core (hand) | Rust | Vectors, JS, Python, trace |
|---|---|---|---|---|
| `mt_session_upd = 4` | `envelope_msg_session_upd_m_c` | — | `Message::SessionUpd` | `"session_upd"` |
| `sess_state` (enum) | `struct sess_state_r`, `.sess_state_choice` | `sess_state_t` | `SessState` | `sess_state` |
| `sess_state_work = 1` | `sess_state_work_m_c` | `SESS_WORK` | `SessState::Work` | `"work"` |
| `cmd_op_notify_done = 8` | `cmd_op_notify_done_m_c` | `LINK_OP_NOTIFY_DONE` | `CmdOp::NotifyDone` | `"notify_done"` |
| `session` (map) | `struct session` | `session_t` | `Session` | — |
| `session` key 8, `; tst` | `session_uint8uint` | `tst` | `tst` | `"tst"` |
| `proto` minor | `hello_major_l_minor` | `LINK_PROTO_MINOR` in `link.h` | `PROTO: Version(0, 24)` | `[0, 24]` |

- **PROTO-7. Rust spells an enum as the UpperCamelCase of its CDDL name, a variant as the
  UpperCamelCase of the value without the enum prefix, a message as the UpperCamelCase of the `mt_`
  name, and a field as the symbolic name.** Measured: all 25 enums, 133 values, 37 message types and
  every map key follow this. The exceptions: the `result` body is `CmdResult` (it would clash with
  `std::result::Result`), and `proto` is `Version`. `review`; `planned: phase 2` (generated)
- **PROTO-8. C core enums carry the C type `<name>_t` and constants in UPPER_SNAKE with a module
  prefix (c.md naming).** Today the prefixes are short forms: `SESS_` (`sess_state`), `ATT_`
  (`att_kind`), `ACT_` (`action`), `PM_` (`perm_mode`), `PRS_` (`pr_state`), `ALERT_` (`alert_mode`),
  `DBG_` (`log_level`), `LINK_OP_` (`cmd_op`), `SCROLL_` (`scroll_unit`), `BENCH_OP_`, `GK_`/`GS_`/`GL_`
  (graph node bits). New hand enums use the full CDDL enum name as the prefix (`FW_STATUS_GO`). When
  the generator lands, the hand enums are replaced by its header, one at a time. `review`;
  `planned: phase 2`
- **PROTO-9. No bare protocol numbers in code.** Use the named constant (`FW_STATUS_BAD`,
  `RESULT_ERR_DENIED` in `link.h`), not `ack(3, …)` or `err == 1`. `review`; `planned: phase 3` (clang-tidy magic-number on changed lines)
- **PROTO-10. JS and Python use the CDDL spelling unchanged** (snake_case strings), because they
  read and write the symbolic vectors. `checked: vectors` (a wrong name fails the round trip)

## 4. Numbers

- **PROTO-11. Map keys are small integers, scoped per map.** Key 0 in `session` is unrelated to key 0
  in `hello`. Numbers 0-23 encode in one byte; prefer them for keys sent often. `review`
- **PROTO-12. Never reuse or renumber a message type, a key or an enum value.** A device in a drawer
  still speaks the old meaning. To retire one, leave its line in the CDDL as a comment: `; 27-29
  reserved (was …)`. Unexplained gaps exist today (`session` keys 27-29): treat any gap as reserved
  until a comment says otherwise. `review`
- **PROTO-13. Message types below 64 are the product protocol; 64 and up are debug and
  observability** (`dbg_*`). Today 1-28 and 64-72 are in use. Take the next free number in the right range. `review`
- **PROTO-14. An open-ended enum keeps a catch-all value**: `agent_other = 15`,
  `device_class_other = 15`. New values go below it. A new enum puts its "none" or "unknown" value at
  0 when it has one (`pr_state_none = 0`). Protobuf's `_UNSPECIFIED = 0` is not adopted for existing
  enums: it would renumber them. `review`
- **PROTO-15. Encode map keys in ascending order.** The device's zcbor decoder reads a map in schema
  order. Rust encodes fields in declaration order, which is key order, and `gen_vectors.py` writes
  keys in order. `checked: vectors`

## 5. Versions

The protocol version is `[major, minor]`, sent in `hello` (device) and `welcome` (daemon). It is
**0.24** on both sides today. The history is the comment above `hello_major_l_minor` in
`firmware/components/core/src/link_tx.c` (0.4 to 0.24).

- **PROTO-16. Bump the minor for every wire change**: a new message type, key or enum value, or a
  changed meaning or limit (0.16 raised the transcript limit to 2047 bytes). One bump per change that
  lands on `main`, not per commit. `review`
- **PROTO-17. A bump changes, in one commit:** the CDDL comment of what was added (PROTO-6),
  `PROTO` in `agentlink-proto/src/lib.rs`, `LINK_PROTO_MINOR` in `link.h` and the history comment in `link_tx.c`, the
  `*_MINOR` gate in `agentlinkd/src/device.rs` (and in the core module that uses it, e.g.
  `GRAPH_MINOR`), the "(proto 0.N)" tag in PROTOCOL.md, and the changelog (PROTO-24). `review`;
  `planned: phase 2` (the generator emits one version constant per language)
- **PROTO-18. Bump the major only for a change that gating cannot hide**: removing or retyping a
  required key, or changing the envelope. PROTOCOL.md §3 says the majors must match.
  The major has never changed. `review`
- **PROTO-19. Name each gate after its feature: `<FEATURE>_MINOR`** (`JOBS_MINOR`, `GRAPH_MINOR`).
  Not `QUEUE_MIN_MINOR` (ui_agent.c), not a bare `peer_minor < 2` (device.rs). `review`

## 6. Compatibility

Receivers do not all ignore unknown keys and message types (the CDDL header and PROTOCOL.md §2 say
so since issue 20261123-d242):

- The daemon's minicbor decoder skips unknown keys and keeps an unknown type as `Message::Unknown`.
- The device's zcbor decoder fails a map that has a key it does not know, or an enum value it does
  not know, and drops the message. A message type it does not know is dropped too.

So compatibility rests on the sender:

- **PROTO-20. The sender never sends what the peer's minor does not know.** The daemon strips keys,
  maps new enum values to old ones and withholds messages by `peer_minor`; the device does the same
  with the daemon's minor (`model_peer_minor()`). Every new key, value or type comes with its gate in
  the same commit. `review`; `planned: phase 2` (an old-peer vector per gate)

  ```rust
  // device.rs: an older device cannot decode agent_pi, so it gets agent_other
  if self.peer_minor < PI_MINOR && s.ag == Some(Agent::Pi) { s.ag = Some(Agent::Other); }
  ```

- **PROTO-21. New keys are optional (`? n =>`).** A required key in an existing map is a major
  change. `review`
- **PROTO-22. When an unknown value must not cost the whole message, send it as a plain `uint`**, as
  `attention.scope` (key 14) does: a device that does not know the value drops the rule, not the
  request. `review`
- **PROTO-23. Receivers still ignore what they can.** New decoders (Rust, JS, a future device) skip
  unknown keys and types, as the CDDL says. `checked: vectors` (Rust keeps `Unknown`)

## 7. Changelog, vectors and generated code

- **PROTO-24. Every minor bump adds an entry to `protocol/CHANGELOG.md`** in
  [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) form: one `## 0.N` section with `Added` /
  `Changed` / `Deprecated` lines naming the keys and types and the design doc. The file does not exist
  yet; the first one is seeded from the `link_tx.c` comment. `planned: phase 2`
- **PROTO-25. Every new message type or key gets a vector** in `gen_vectors.py`, then
  `uv run protocol/tools/gen_vectors.py`. Every type has one today (§1). `checked:
  scripts/check protocol` (validate, regenerate, `git diff --exit-code protocol/vectors`), `planned:
  phase 2` for the coverage count
- **PROTO-26. Never edit the zcbor output by hand.** Change the CDDL and run
  `firmware/components/agentlink_proto/regen.sh` (pins zcbor 0.9.1 and `cbor2<5.7`, applies
  `patches/`). Commit the CDDL and the regenerated files together. `checked: scripts/check protocol`
  (`regen.sh --check` regenerates into a temporary directory and diffs, structure.md S-GEN-01)
- **PROTO-27. Names will be generated, not copied.** Phase 2 adds a generator that reads the CDDL
  (rule names, constants and the PROTO-3 comment names) and writes the C enum header, the Rust
  `enums.rs` and message table, the JS `MSG_TYPES`/`ENUMS` and the Python `MT`, each with a
  "GENERATED … do not edit" line. `scripts/check protocol` regenerates and diffs them. Until then,
  a change to a protocol name edits every copy in §1 in the same commit. `planned: phase 2`

The order of work for a new message is structure.md S-NEW-03.

## 8. Drift found on 2026-11-22

`envelope.rs`), JS (`messages.js`), the C core enums (71 values) and the regenerated zcbor codec.
Every CDDL key name was also compared with its Rust field. **No value differs anywhere.** The name
and coverage drift:

Issue 20261123-d242 fixed the rest on 2026-11-25: the CDDL and PROTOCOL.md state the real
