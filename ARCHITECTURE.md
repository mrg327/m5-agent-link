# Architecture

This page is the map: what the system is, where each part lives and which rules hold the parts
apart. It names files and types to search for rather than linking into source, so it stays true as
the code moves. The rules themselves are in [docs/conventions/structure.md](docs/conventions/structure.md);
the designs are in [docs/design/](docs/design/), starting with [DESIGN.md](docs/design/DESIGN.md),
[PROTOCOL.md](docs/design/PROTOCOL.md) and [FIRMWARE.md](docs/design/FIRMWARE.md). For a visual
guide, open the Atlas (`scripts/atlas --open`).

## Bird's-eye view

A watch (first the M5Stack StopWatch) shows the state of AI coding agents running on a PC: Claude
Code, the Copilot CLI and the Copilot cloud agent. When an agent finishes or needs you, the watch
buzzes. You can approve or deny a permission request, answer a question, or bring that agent's
terminal to the front, all from the wrist.

```text
 agents --hooks--> agentlink-hook --IPC--> agentlinkd --BLE / USB / WebSocket--> watch firmware
 (Claude Code,      (tiny, fail-open)      (Rust daemon:                         (ESP32-S3 + LVGL:
  Copilot)                                  sessions, broker, focus)              core + board HAL)
```

The daemon sends meaning, never pixels: sessions, states and attention requests, encoded as CBOR
from one CDDL schema (`protocol/agentlink.cddl`). Each device declares its capabilities in `hello`
and draws what it can. Everything is traced: the daemon writes a JSONL trace and an audit log under
`~/.agentlink/`, and the watch prints `#` debug lines over USB.

Three runtimes share one C core:

| Runtime | What runs | Talks to the daemon over |
|---|---|---|
| Watch firmware | `firmware/`: ESP-IDF app, `core` + `boards/stopwatch` | BLE GATT or USB serial |
| Daemon | `daemon/`: `agentlinkd` (service), `agentlink` (CLI), `agentlink-hook` (hook shim) | - |
| Simulator and Atlas | the same `core` on SDL2 (`simulator/`) and in WebAssembly (`atlas/wasm/`) | WebSocket (`127.0.0.1:7878`) or in-page frames |

`core` builds against three implementations of one header, `hal.h`. That the simulator and the
browser run the real core is the proof that the port boundary is real.

## Code map

### `firmware/` (C, C++)

- `components/core/` The portable watch logic, C11. Entry points `core_init()` and `core_step()`
  (`include/core.h`, implemented in `src/app.c`). Single-threaded: HAL callbacks only push into
  rings (`ring.c`); everything else, LVGL included, runs in `core_step()`. Inside `src/`, four tiers
  (structure.md "Inside core"): glue (`app`, `link*`, `ota`, `power*`, `bench`, `debug.c`), UI
  (`ui_*.c`, one file per screen; actions go up through `ui_actions_t`), services (`prefs`, `sound`,
  `feedback`, `voice`, `keys`) and pure, host-tested modules (`model`, `nav`, `gesture`, `steps`,
  `graph`, `ring`, `gauges`, `detail`, `done`, `motion`, `sha256`, `sound_bank`). `src/fonts/` is
  generated; `third_party/detools` is vendored (delta OTA).
- `components/agentlink_hal/` One header, `hal.h`: the contract every board and host implements
  (display, touch, buttons, motion, haptic, audio, mic, prefs, power, link, OTA). `hal_board_info()`
  returns the `caps` that core decides by.
- `components/agentlink_proto/` The C codec generated by zcbor from the CDDL
  (`agentlink_codec_{encode,decode,types}.h`), plus vendored `zcbor_*`. `regen.sh` regenerates it.
- `boards/stopwatch/` The StopWatch implementation of `hal.h`: `display.cpp` (M5GFX, CO5300
  AMOLED), `touch.cpp`, `input.cpp`, `imu.cpp`, `audio.cpp`, `mic.cpp`, `link_ble.cpp` (NimBLE),
  `link_usb.cpp`, `ota.cpp`, `rtc.cpp`, `board.cpp`; `sw_power/` drives the PMIC and I/O expander.
- `main/main.c` ESP-IDF entry: board init, LVGL init, display and touch, then the core loop.
- `tools/` Firmware helpers: `fonts/gen.mjs` (icon and text fonts), `check_dram.py` (the internal RAM
  budget).

### `simulator/` (C)

The same `core` on SDL2, linked to the daemon over WebSocket. `src/sim_*.c` (except the two below)
form the host `agentlink_hal`; `src/main.c`, `sim_script.c` (the script runner: `tap`, `shot`,
`expect` lines) and `sim_fw_image.c` are the white-box harness. `tests/test_*.c` unit-test the pure
modules; `scripts/*.txt` are screen scripts run by `ctest`.

### `daemon/` (Rust, TypeScript, Python)

- `crates/agentlinkd` The service. `hook_source.rs` (hook IPC to events), `registry.rs` (the session
  list and its deltas), `broker.rs` (`Broker`: each pending request has a `rid`; the first answer
  wins), `device.rs` (hello, welcome, snapshot, deltas, attentions, `cmd` handling), `transport.rs`
  (`Transport` and `Link` traits) with `ble.rs`, `usb.rs`, `ws.rs`; `focus/` (`FocusDriver`: kitty,
  Terminal.app, Windows Terminal, tmux), `trace.rs` (JSONL trace and audit log), `ota.rs`, `jobs.rs`.
- `crates/agentlink` The CLI: `status`, `trace`, `decode`, `hooks`, `ota`, `bench`, `remote`, `ssh`.
  It talks to the daemon over its socket.
- `crates/agentlink-hook` The hook shim agents run: reads the hook JSON on stdin, forwards it to
  `hook.sock`, always exits 0, prints a decision only for a blocking `PermissionRequest`.
- `crates/agentlink-proto` Hand-written wire types and CBOR codec (`Envelope`, `Message`), held to
  the CDDL by `protocol/vectors/`.
- `crates/agentlink-keys`, `crates/agentlink-delta` Pure libraries: the watch keyboard's decoder and
  lexicon; the bsdiff and heatshrink encoder for delta OTA.
- `integrations/` Agent extensions (`pi/`). `tools/` End-to-end tests (`*_e2e.py`) and `launchd.sh`.

### `protocol/` (CDDL, Python)

`agentlink.cddl` is normative. `vectors/*.json` (symbolic JSON plus `cbor_hex`, generated by
`tools/gen_vectors.py`) are round-tripped by the C codec, the Rust crate and the Atlas;
`tools/validate_vectors.py` checks them against the schema. `fixtures/ota/` holds delta-OTA fixtures.

### `index.html`, `atlas/` (JS, Python, C)

The Atlas, an interactive guide with no build step. `atlas/js/` (chapters: `flow/`, `gestures/`,
`stage/`, `replay/`, `sound/`, the `bus.js` event bus), `atlas/data/facts.json` and
`atlas/css/tokens.generated.css` (extracted from source by `atlas/tools/extract.py`), `atlas/wasm/`
(`web_hal.c` and `web_main.c`: core built with Emscripten into `atlas/vendor/watch.{js,wasm}`).
Ownership rules are in `atlas/CONTRACT.md`.

### The rest

- `bench/` Task scripts the bench plays on the real watch as a finger (`agentlink bench`, BENCH.md).
- `design/` Design-board state (`board/*.json`), written by `tools/board`.
- `docs/` `design/` and `research/` are ours, `conventions/` holds the rules, the rest is a vendor
  documentation mirror (`scripts/fetch_docs.py`).
- `issues/` The shared work log, one Markdown file per issue, driven by `scripts/issue`.
- `scripts/` Repo-wide entry points: `check` (every check; `check.d/` holds the scripts), `issue`,
  `atlas`, `fetch_docs.py`.
- `tools/` Standalone tools with their own README: `board/` (the design board), `linux/`.

## One approval, end to end

Claude Code wants to run `npm test` and asks for permission.

1. **Agent hook.** Claude Code runs `agentlink-hook claude PermissionRequest` with the request JSON on
   stdin. The hook connects to `$AGENTLINK_HOME/hook.sock` (a named pipe on Windows; a TCP tunnel for
   a remote machine) and waits. If the daemon is not there it exits 0 silently, and the terminal
   prompt appears as usual: the hook fails open and silence never approves.
2. **Daemon.** `hook_source.rs` turns the message into a `broker::Request` and calls
   `Broker::open_with`, which assigns a `rid` and returns a one-shot receiver. The answer window
   (60 s by default, ANSWER-WINDOW.md) starts. The registry marks the session as waiting, and every
   connected device gets a `Message::Attention` from `device.rs`. The trace records each step.
3. **Protocol.** The attention is a CBOR `envelope` (`attention` in `agentlink.cddl`: `rid`, `sid`,
   kind, title, detail, optional standing rule). It travels in BLE GATT fragments (`ble/frag.rs`),
   USB frames (`usb/frame.rs`) or WebSocket messages.
4. **Watch.** The board's link driver calls the `on_rx` callback given to `hal_link_start()`. Core's
   `on_rx` in `app.c` only copies the frame into a ring; `core_step()` later decodes it with the zcbor
   codec, and `link_rx.c` (`on_attention`) stores an `attention_t` in the model. `feedback.c` plays
   the haptic pattern, and the UI shows the request card (`ui_ask.c`), its ring counting down the
   window.
5. **User.** A hold on Approve calls the `approve` callback in `ui_actions_t`, which reaches
   `act_approve()` in `app.c`. It sends `cmd{op: approve, sid, rid, hold}` through `link_send_cmd()`
   (`link_tx.c`, encoded by the codec) and `hal_link_send()`.
6. **Back.** `device.rs` handles `CmdOp::Approve` and calls `Broker::answer(rid, Decision::Approve)`;
   the first answer wins, so a later one from another device or the terminal is refused. The
   one-shot fires, `hook_source.rs` replies on the hook connection, and `agentlink-hook` prints the
   `hookSpecificOutput` decision. Claude Code runs the command. The daemon sends `clear` so every
   watch drops the card, and the decision goes to `~/.agentlink/audit.jsonl`.

The same path carries Deny, a standing rule (`cmd.rh`, STANDING-RULES.md) and answers to questions;
Copilot prompts are answered by typing into the terminal instead (`prompt.rs`).

## Invariants

Each rule is enforced by `scripts/check structure` (`python3 scripts/check.d/structure.py`) unless
another check is named. Existing exceptions are listed in `scripts/check.d/baselines/structure.txt`,
which only shrinks.

- **S-DEP-01** `core` includes only its own headers, `hal.h`, the codec, `lvgl.h` and the C library. `checked: scripts/check structure`, build.
- **S-DEP-02** ESP-IDF and FreeRTOS headers in `core` only under `#ifdef ESP_PLATFORM`. `checked: scripts/check structure`.
- **S-DEP-03** `hal.h` includes only the C library and `lvgl.h`. `checked: scripts/check structure`, build.
- **S-DEP-04** `agentlink_proto` includes only itself and the C library. `checked: scripts/check structure`, build.
- **S-DEP-05** A board never includes `core` or codec headers. `checked: scripts/check structure`, build.
- **S-DEP-06** `firmware/main` and `atlas/wasm/web_main.c` use only the public `core.h`. `checked: scripts/check structure`.
- **S-DEP-07** A host HAL (`simulator/src/sim_*.c`, `atlas/wasm/web_hal.c`) never includes `core`. `checked: scripts/check structure`.
- **S-DEP-09** No `#include` path contains `..`. `checked: scripts/check structure`.
- **S-DEP-10** Every function in `hal.h` is defined by every HAL. `checked: scripts/check structure`, link.
- **S-CORE-01** Pure modules use no `hal.h`, no LVGL and no UI header. `checked: scripts/check structure`, ctest.
- **S-CORE-02** Services use `hal.h` and `link.h`, never LVGL or UI headers. `checked: scripts/check structure`.
- **S-CORE-03** UI files never include glue headers; actions go up through `ui_actions_t`. `checked: scripts/check structure`.
- **S-CORE-04** LVGL only in UI and glue, and only from `core_step()`'s thread. `checked: scripts/check structure` (include half); `review`.
- **S-CORE-05** Core decides by `hal_board_info()->caps`, not by board name. `review`.
- **S-CRATE-01** Library crates depend on no workspace crate. `checked: scripts/check structure`.
- **S-CRATE-02** No crate depends on a binary crate; binaries talk over IPC. `checked: scripts/check structure`, cargo.
- **S-CRATE-03** `agentlink-hook` depends on no workspace crate. `checked: scripts/check structure`.
- **S-CRATE-04** Workspace crate dependencies go through `[workspace.dependencies]`. `checked: scripts/check structure`.
- **S-GEN-01** A generated file is never edited by hand. `review`; vectors and atlas facts are regenerated and diffed.
- **S-GEN-02** Generated and vendored files are marked in `.gitattributes`. `checked: scripts/check structure`.
- **S-NEW-01** Every `core/src/*.c` is in `CORE_SRCS`. `checked: scripts/check structure`.
- **S-TOP-01** Every top-level directory is in the `README.md` map and structure.md. `checked: scripts/check structure`.
- **S-OWN-01** Every top-level directory has a `.github/CODEOWNERS` entry. `checked: scripts/check structure`.
- **S-DOC-01** Every build unit has a README or a row in its parent's README. `checked: scripts/check structure`.
- **Protocol** The CDDL, the C codec, the Rust crate and the Atlas agree. `checked: scripts/check protocol` (vectors), `scripts/check atlas`.

The code-level rules (C, Rust, Python, JS, names) are in [docs/conventions/](docs/conventions/README.md).
